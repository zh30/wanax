蚁后 Wanax — 低保真线框图

v1 无 GUI：「屏」= 终端输出态（stdout/stderr）+ 文件内容态。依据 docs/PRD.md 与现有 CLI 实现文案绘制。黑白灰，仅表达信息层级、核心文案、操作位置与页面状态。

读图约定

黑头条 = 终端命令及其输出（前景进程）
灰头条 = 文件（路径见条内）
虚线灰块 = 占位块（长输出/正文省略）
chip = 该屏覆盖的状态类型
▸ 操作 / 去向 = 可执行动作 → 结果屏编号

流程总览（点击屏号跳转）

A · 首次准备（每个仓库一次性）

顺序：init → 写契约 → 配 config + 环境变量 → doctor 体检。任一步失败都不产生 Run。

A-1wanax init — 初始化成功首次使用 · 步骤 1/4
正常首次使用
$ wanax init # 在 git 仓库根目录
initialized .wanax/ and specs/example.contract.md
Next: git add .wanax/config.toml specs/
生成但未 commit 的文件
.wanax/config.toml      # 工厂配置模板
.wanax/.gitignore       # 忽略 worktrees/ LOCK *.db credentials*
specs/example.contract.md # 契约模板

▸ 可执行操作编辑契约 → A-3；git add … && git commit 后 → A-4

▸ 去向成功 → A-3；失败 → A-2

A-2wanax init — 两个失败态首次使用 · 步骤 1/4 的异常
失败
$ wanax init # 目录不是 git 仓库
ERROR E_NOT_GIT not a git repository
exit 2 · 不写任何文件
$ wanax init # .wanax/config.toml 已存在
ERROR E_ALREADY_INIT already initialized
exit 3 · --force 可强制重建

▸ 可执行操作进入/初始化 git 仓库重跑；或 wanax init --force

▸ 去向修复后 → A-1

A-3编辑契约 specs/foo.contract.md首次使用 · 步骤 2/4 · 每次任务都要写
正常核心输入屏
specs/split-timeout.contract.md — 人编辑，启动后 hash 冻结
---
spec: wanax.contract
version: 1
name: "split-timeout-module"
test_command: "cargo test -p foo --timeout-mod"
test_timeout_secs: 180
allowed_globs:
  - "crates/foo/src/**"
  - "crates/foo/tests/**"
forbidden_globs:
  - "**/.env"
---
〔正文〕## Intent — 要做什么（1–4000 字符）
〔正文〕## Decisions — 不可重开的决策（1–50 条）
〔正文〕## Boundaries — 允许/禁止路径
〔正文〕## Completion Criteria — CC-01…CC-NN 可机检断言
CC-03 可绑 bound_test: timeout_expires_returns_error

校验红线（违反 → B-1 / B-5）

test_command 非空 · allowed_globs ≥1 条 · CC ≥1 条
test_command 禁止 rm/sudo/dd/curl|/> 写根目录
绑定测试放 tests/** 且不进 allowed_globs（否则 B-6 警告）

▸ 可执行操作保存 + git commit → A-4 / A-5 → wanax start

▸ 去向字段缺失 → B-1；危险命令 → B-5；合格 → C-1

A-4config.toml + 环境变量（凭据/权限）首次使用 · 步骤 3/4 · 权限申请等价物
权限/凭据一次性
~/.wanax/config.toml（repo 内 .wanax/config.toml 覆盖同名键）
[commander]
provider = "openai_compat"   # anthropic|openai|openai_compat|claude_cli|codex_cli
model = "gpt-4.1"
base_url = "https://api.openai.com/v1"

[inner]
provider = "openai_compat"
model = "gpt-4.1-mini"

[reviewer]  # 空 → 自审降级 mechanical，tombstone 标 self_review=degraded
[worker]
adapter = "octoscode"       # octoscode|fake|cmd|claude|codex
timeout_secs = 1800         # 超时 → E_WORKER_TIMEOUT → E-6
[git]
protected_refs = ["main","master"]  # → E-7
[lock]
repo_exclusive = true       # false → 按 allowed_globs 路径锁，不相交可并行
[budget]
max_usd = "5.00"
max_inner_turns = 40
$ 凭据只走环境变量，禁止写进 git / Tombstone
export WANAX_COMMANDER_API_KEY='…' # HTTP commander 必需；claude_cli/codex_cli 不需要
export WANAX_INNER_API_KEY='…'      # 仅当 reviewer.model 与 inner.model 不同时需要

▸ 可执行操作wanax doctor [--strict] 自检 → A-5 / A-6

▸ 去向缺 key 仍可先跑（fallback 机械 commander）；--strict 缺 key → B-4 exit 8

▸ 去向任一项异常 → A-6 警告态

A-6wanax doctor — 警告 / strict 失败首次使用 · 步骤 4/4 的异常
权限缺失警告失败(--strict)

▸ 可执行操作补 key → A-4；装 adapter；--fix-lock → F-3；把 tests/** 移出 allowed_globs → A-3

▸ 去向--strict 且 key 缺失 → exit 8 E_MISSING_API_KEY；tests 可写 → exit 4

B · 启动门 — wanax start 前置校验（失败均不建 Run、不留锁）

契约校验 → 脏树 → 锁 → adapter/key → 危险命令，逐项拦截。任一拒绝都直接回终端，exit 非 0。

B-1start — 契约不合格启动门 · 校验第 1 关
失败
$ wanax start --contract specs/foo.contract.md
ERROR E_CONTRACT_INVALID invalid contract: missing allowed_globs, completion_criteria
exit 4 · 列出缺失字段 · 不创建 Run

▸ 可执行操作回 A-3 补齐四段与 front matter

▸ 去向修好重跑 → C-1

B-2start — 工作区脏启动门 · 校验第 2 关
失败
$ git status --short
 M src/lib.rs          # .wanax/ 以外的未提交变更
$ wanax start --contract specs/foo.contract.md
ERROR E_DIRTY_WORKTREE dirty worktree; commit, stash, or pass --allow-dirty
exit 5 · base_sha 需可信，默认不替人兜底

▸ 可执行操作commit / stash 后重跑；或显式 --allow-dirty

▸ 去向干净 → C-1

B-3start — 仓库被锁启动门 · 校验第 3 关
失败恢复入口
$ wanax start --contract specs/bar.contract.md

exit 6 · 打印占锁 run_id；path-set 模式下 allowed_globs 相交同此报错

▸ 可执行操作wanax status wx_01K3ACTIVE… → D-2；等其终态；或 cancel → F-1；pid 死 → doctor --fix-lock → F-3

▸ 去向锁释放后重跑 → C-1；不相交契约（path-set）→ 并行 C-1

B-4start — adapter / key 缺失启动门 · 权限与依赖

exit 8 · claude_cli/codex_cli 不需要此 key

▸ 可执行操作装对应 CLI 或改 worker.adapter/commander.provider；export key → A-4

▸ 去向修复 → A-5 → C-1

B-5start — 危险 test_command启动门 · 安全校验
失败安全

▸ 可执行操作回 A-3 改成白名单命令（cargo test / npm test / pytest / go test / make test …）

▸ 去向合格 → C-1

B-6start — 绑定测试可写警告启动门 · 警告但放行
警告正常
specs/foo.contract.md（摘录）

  - "src/**"
  - "tests/**"   # ⚠ 工人可改写验收测试 → 外环复测形同虚设
$ wanax start --contract specs/foo.contract.md
# tombstone 记 WARN 事件 E_CONTRACT_TESTS_WRITABLE，不阻断
wx_01K3RUN…

▸ 可执行操作默认继续 → C-1；稳妥做法回 A-3 把 tests/** 移出 allowed

▸ 去向放行进入主流程；doctor --strict 下同情形 exit 4 → A-6

C · 主流程 — 一次 wanax start 的前台输出流（Flow A）

同一命令的连续输出按段平铺为 C-1 → C-2 → C-3。全程无人值守：无交互提示、无 spinner；人可以离开键盘（tmux / systemd --user 挂后台），不能离开契约。

C-1start · 冻结 → 派发 → 内环工作主流程 · 步骤 1/3
加载/工作中正常
$ wanax start --contract specs/foo.contract.md # 可加 --adapter octoscode|fake|cmd|claude|codex
wx_01K3RUN…                    # run_id（ULID）
state=contract_ready           # 契约 sha256 冻结 · base_sha=HEAD · 建 wanax/<run>/inner|outer 分支
state=dispatched               # 写 LOCK · tombstone run_started · Commander 产出 1 个 WorkUnit
                               #   Commander JSON 非法 → 重试×2 → E-6 E_COMMANDER_SCHEMA
state=inner_working
starting worker pid=4242       # inner worktree 拉起 adapter；env 注入 WANAX_RUN_ID/WORK_UNIT_ID/TEST_COMMAND
                               #   不注入 GIT_ASKPASS / GH_TOKEN / ssh 转发（E-7）

期间持续发生（不在 stdout 逐条显示）

每轮工具循环 spent_inner_turns+1 · 每次 LLM 调用记 budget_tick
超限即停 → E-5；worker 崩溃/超时 → E-6

▸ 可执行操作另开终端 wanax status → D-1/D-2；wanax cancel → F-1；或挂 tmux 离开

▸ 去向worker 退出且收齐回执 → C-2

C-2start · 回执 → 外环换树复测主流程 · 步骤 2/3
加载/工作中正常
（同一 start 输出流 · 续）
state=receipt_ready            # supervisor 提交 inner commit wx(<run>): <title> + 写 Receipt
                               #   Receipt.claimed_pass 只记录，不作数（FR-009）
state=outer_reviewing          # 新建 outer worktree · checkout inner_sha · 重跑 test_command
                               #   + glob 边界检查（forbidden 命中 → boundary_ok=false）
                               #   + Commander 出 Verdict（不读 inner transcript）

accept 机械前置（FR-014，模型不可覆盖）

outer exit==0 · boundary_ok · receipt.test_command==契约
inner_sha 是 base 后代 · changed_files 非空 · 预算未耗尽 · rework≤3
外环复测超时 → outer_test_exit_code=124 → 不得 accept → E-1/E-2

▸ 可执行操作等待；旁观 D-2/D-5

▸ 去向accept → C-3；rework → E-1；reject → E-3；escalate → E-2；模型想 accept 但测试红 → E-4

C-3start · accepted 收尾主流程 · 步骤 3/3 · 终态
正常终态
（同一 start 输出流 · 末段）
state=accepted
wanax/wx_01K3RUN…/inner        # ← 交付的本地分支
 src/timeout.rs | 42 +++++++++++++++++-----------
 1 file changed, 28 insertions(+), 14 deletions(-)
pr=https://github.com/…/pull/12 # 仅 github.create_pr=true 或 WANAX_CREATE_PR=1（默认不开）
同步落盘
.wanax/runs/<id>/RESULT.md    # → D-6
LOCK 释放 · 主 worktree 不自动 merge

▸ 可执行操作人审分支后自行 git merge wanax/<id>/inner —— P0 禁止 wanax accept 人工盖章

▸ 去向流程结束；审计 → D-5

D · 旁观查看 — 运行中 / 事后随时可用

只读命令，不改变 Run 状态。均支持 [run_id] 详情模式；未知 id → F-4。

D-5TOMBSTONE.md — 审计账本文件 · 每 Run 一份 · append-only

▸ 可执行操作人读 / 喂给工具回放任一 Run：谁派的、测了什么、判了什么

▸ 去向escalate 排障第一站 → E-2

D-6RESULT.md — 终态摘要文件文件 · 仅 accept/reject 后生成
正常空态
.wanax/runs/wx_01K3RUN…/RESULT.md

〔test excerpt〕outer 复测输出摘录（≤8000 字符）

空态

非终态（含 cancelled/failed/escalate/budget_exhausted）→ 文件不存在

▸ 可执行操作—（产物文件）

▸ 去向reject 详情回 E-3 / D-4

E · 分叉与终态 — 非 happy path

rework 是唯一非终态分支（≤3 次自动重试）；其余五个为终态，保留现场与分支由人接手。

E-1rework — 自动返工循环分叉 · 非终态 · 最多 3 次
恢复正常
（同一 start 输出流 · verdict=rework）
state=rework        # rework_count+1；新 instruction 携带失败 exit code + 失败测试摘录
state=dispatched    # 同一 WorkUnit 重新进入 C-1 派发
state=inner_working
…
state=accepted      # 第二次绿 → C-3

▸ 可执行操作旁观 D-2（rework_count 递增）；不想等 → F-1 cancel

▸ 去向≤3 次 → 继续循环；第 4 次仍败 → E-2 escalate

E-2escalate — 转人工终态
失败终态
（start 输出流 · 末段 · 撞返工上限强制 escalate）
state=escalate
ERROR E_REWORK_LIMIT max rework exceeded
exit 非 0 · 放锁 · worktree / tombstone / inner 分支全部保留
（变体 · commander 主动 escalate）
state=escalate
ERROR E_ESCALATE <commander reason>
# verdict.reason 直接透出 · 例：需求超出契约范围需人工

▸ 可执行操作D-5 看完整事件链定位；D-4 看最后 verdict；改契约/拆小任务 → 新 Run C-1

▸ 去向人可直接接管 inner 分支（工厂不阻拦）

E-3rejected — 裁决拒绝终态
失败终态安全
（start 输出流 · 末段 · 越界拒）
state=rejected
ERROR E_BOUNDARY boundary check failed: Cargo.toml
exit 非 0 · 列出越界路径 · 写 RESULT.md（D-6）
（变体 · 其他原因 reject —— E_REJECTED）
state=rejected
ERROR E_REJECTED <commander reason>
# 例：changed_files 为空、receipt.test_command 与契约不一致等

▸ 可执行操作看 D-6 RESULT / D-4 verdict reason；修边界 → A-3 新 Run

▸ 去向分支仍在，人可自行决定是否捡回部分改动

E-4E_ACCEPT_OVERRIDE — 模型越权被拦分叉 · 安全网
安全恢复
